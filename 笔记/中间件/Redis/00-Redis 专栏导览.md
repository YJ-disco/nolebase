# Redis 专栏导览

这一栏收录 Redis 的内部机制：数据在内存里以什么结构存放、一条命令为什么快、进程退出后数据怎么留下、内存满了淘汰谁、多节点怎么共用一把锁，以及拿它当缓存时怎么处理雪崩、击穿与双写不一致。

| 不收 | 去哪看 | 本专栏只关心 |
| --- | --- | --- |
| 缓存穿透、雪崩在业务层的完整治理与网关限流 | 各自业务的缓存设计文档 | Redis 视角下这三类异常与双写一致性的机制 |
| 分布式一致性的通用理论（CAP、共识算法、Raft） | `分布式` | Redis 自己用哪套机制做复制与故障转移 |
| 消息队列的投递语义、顺序保证与消费位点 | `中间件/MQ` | Redis 的 Stream 作为轻量消息队列的边界 |
| 键值存储的持久化理论、LSM 树与 WAL | `中间件/MySQL` | Redis 的 AOF 与 RDB 两条落盘路径 |

## 阅读顺序

**01 → 02 → 03 → 04 → 05 → 06 → 07**。这条顺序是一条依赖链，不按热门程度排。

01 给全局骨架：Redis 是什么、为什么快、命令怎么被执行，后面每一篇都落在这个模型上。02 接在 01 之后，因为「为什么快」有一半答案在数据结构 —— 九类类型与它们的底层实现决定了每条命令的复杂度。03 与 04 是一组，管「数据怎么留住、内存怎么腾出来」：03 讲持久化的两条落盘路径，04 讲键过期与内存淘汰，两者都会碰到同一批大 Key 与 `maxmemory` 参数。05 是并发控制的一侧，依赖 02 的 `SET NX` 语义与 Lua 的原子性。06 把视野从单机拉到多节点：主从复制是哨兵与 Cluster 的共同底座，哨兵解决「主库宕了谁顶上」，Cluster 再加一层分片。07 收尾，把前面所有机制放进「拿 Redis 当缓存」这一个具体场景里，处理雪崩、击穿、穿透与数据库双写不一致。
