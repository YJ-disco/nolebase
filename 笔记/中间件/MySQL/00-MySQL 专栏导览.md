# MySQL 专栏导览

这一栏收录 MySQL 与 InnoDB 的内部机制：一条 SQL 怎么被解析、优化、执行，数据落在磁盘上的哪个位置，索引为什么是 B+ 树，并发事务之间怎么互不干扰，以及崩溃之后数据为什么还在。

| 不收 | 去哪看 | 本专栏只关心 |
| --- | --- | --- |
| 分布式数据库、分库分表与中间件选型 | `分布式/分布式存储` | 单机 MySQL 与 InnoDB 的内部机制 |
| SQL 语法教程、函数手册、备份与部署流程 | MySQL 官方手册 | 一条语句在引擎内部怎么被执行 |
| 消息队列的投递语义与顺序保证 | `中间件/MQ` | 事务、锁、日志、索引、Buffer Pool |
| 操作系统的页缓存、IO 调度与文件系统 | `基本功` | InnoDB 在通用机制之上自己实现了哪一套 |

## 阅读顺序

**01 → 02 → 03 → 04 → 05 → 06 → 07**。这条顺序是一条依赖链，不按热门程度排。

01 给全局骨架，后面每一篇都在往下钻一层。02 是 03 的载体 —— 不了解页与行格式，就说不清 B+ 树的叶节点里到底存了什么；03 是 04 的前提 —— 索引失效的每一类都要回到「B+ 树上的有序性」，而 04 的深度分页与 `count` 优化又直接用到 03 的结论。05 与 06 是一组：事务隔离由 MVCC 与锁两套机制共同实现，只读 05 会以为 MVCC 包办了一切，只读 06 又不知道为什么需要间隙锁。07 放在最后，因为 Buffer Pool、redo、binlog 都在「写入路径」上，读完前面几篇才知道一条 `UPDATE` 改的是哪一层。
