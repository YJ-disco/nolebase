# 分布式计算专栏导览

本专栏收录**"把计算摊到多台机器上"这条线上的编程模型与运行时**：批处理与内存计算、图计算、交互式分析、以及流处理各自是怎么定义数据共享与容错边界的。

它和相邻专栏的分工是**层次**而不是技术栈：

| 不收 | 去哪看 | 本专栏只关心 |
| --- | --- | --- |
| 存储系统自身的内部实现（GFS、Bigtable、Dynamo…） | [[00-分布式存储专栏导览\|分布式存储]] | 计算层把什么当作"稳定存储"、复用它时付什么代价 |
| 共识算法本身（Paxos、Raft、Zab） | [[00-一致性共识算法专栏导览\|一致性共识算法]] | 计算框架的容错走的是共识，还是能靠别的性质绕开 |
| 集群调度与运维（Chubby、Borg、Dapper） | [[00-集群与运维专栏导览\|集群与运维]] | 计算任务被交给谁去放（Borg 那一层） |

换个说法：存储专栏讲"数据放哪"，共识专栏讲"节点怎么达成一致"，本专栏讲**"计算怎么被组织成可并行、可恢复的形状"**。

## 目录

- 01 · [[01-RDD|RDD]] —— 用**粗粒度变换换容错**：血统取代复制、narrow / wide 依赖的分界、checkpoint 的判据
- 02 · [[02-Pregel|Pregel]] —— **顶点中心 + 超步（BSP）**：天然无死锁的通信模型、投票停机、消息合并与聚合器
- 03 · [[03-Dremel|Dremel]] —— **只读嵌套数据的交互式分析**：repetition / definition level 编码与记录装配
- 04 · [[04-Parameter Server|参数服务器]] —— **把"共享参数"系统化**：三层压缩、三种一致性模型、任务依赖图
- 05 · [[05-S4|S4]] —— **流计算的最早形态之一**：为什么批处理平台改造成不了流系统、PE 与 PN 的抽象
- 06 · [[06-Storm|Storm@Twitter]] —— **生产运维视角**：五层架构、acker 机制，以及三个运维故事

## 阅读顺序

**01 → 02 → 03 → 04 → 05 → 06**，按**数据形态**递进：

- **RDD** 立起"内存计算 + 血统"这个地基，后面几篇的容错讨论都回到它；
- **Pregel** 是 RDD 明确声称能表达的一个模型，两篇构成一组正面对照：Pregel 是**专用化**的极致（顶点中心 API + 超步同步 + 只为图优化），RDD 声称能用 200 行库把它表达出来。并读能看清"专用框架"与"通用抽象"的边界落在哪；
- **Dremel** 走另一条路：不迭代，而是把**嵌套结构的列式表示**与树形聚合做出来；
- **Parameter Server** 把"参数"当作被分片的共享状态，是机器学习训练侧的取舍；
- **S4 与 Storm** 是流处理的早期形态与工程化版本，两篇构成一组演进对照。
