# P2P 与路由专栏导览

本专栏收录**结构化覆盖网（structured overlay）与分布式哈希表（DHT）** —— 在一个没有中心目录、节点随时上下线、规模到几十万甚至上百万的自治系统里，**怎么让任何一个节点都能找到某个 key 该由谁负责**。

这四篇都写在 2001 到 2002 年之间，共同的出发点是被 [一致性哈希](../04-一致性哈希算法.md) 打开的那个思路：**把 key 和节点都映射到同一个逻辑空间里，让"找 key"退化成"在空间里朝目标走"**，于是不需要任何目录服务器。四篇的分歧在于**这个逻辑空间长什么样、每个节点要为此记住多少东西**。

| 篇 | 空间 | 路由方式 | 每节点状态 |
| --- | --- | --- | --- |
| 01 · CAN | $d$ 维笛卡尔坐标（环面） | 朝目的坐标贪心转发 | **$2d$（与 $n$ 无关）** |
| 04 · Kademlia | 一圈标识符 + **XOR 度量** | 路由表按位逐级覆盖 | $O(\log n)$ |

一个反复出现的设计张力值得先记下来：**$O(\log n)$ 的路径长度与"每节点状态与系统规模无关"这两件事不能同时要。** 这批四篇给出了四种不同的取舍位置，而不是四个更快的方案。

## 目录

- 01 · [[01-CAN|CAN]] —— **唯一不靠环**的一篇：把哈希桶摊进 $d$ 维坐标空间，节点各领一块区域；邻居的判据是**"在 $d-1$ 个维度重叠、在一个维度相接"**；**为什么故意让 $d$ 与 $n$ 无关**（换来状态数固定）；七项改进（维度 / reality / RTT 加权 / 区域超载 / 多哈希函数 / landmark 分桶 / 均匀划分）与它们各自的收益；bare bones 对 knobs-on-full 的 **198 跳与 23,008 ms → 5 跳与 135 ms**；landmark 那项未进入最终评测
- 02 · [[02-Chord|Chord]] —— 把一致性哈希改造成"每节点只需 $O(\log N)$ 邻居"的那一步：标识符环与 successor、**finger table 的 $2^{i-1}$ 结构与"剩余距离至少折半"的论证**、`stabilize`/`notify` 与 $\log^2 N$ 稳定化条件、**successor list 与 $r=2\log_2 N$**、**weak / strong / loopy 三个定义与 self-search**、**正确性分析全章**（引理 5.5 的归纳证明、定理 5.8 的 $n^2$ 步收口、定理 5.11 的 $O(N^2)$ 与"$2N$ 个指针各最多改进 $N$ 次"的计数、引理 5.12 的子路径论证、定理 5.16 的 $O(N^3)$、pseudoforest / appendage / pseudostar / $c$-ring-like state 一整套定义）；"以高概率"被整套换成"基于标准困难性假设"（用 SHA-1）；实测 $\tfrac{1}{2}\log_2 N$ 的二进制解释与 $e^{-1}=0.368$
- 03 · [[03-Pastry|Pastry]] —— 第一个把**"逻辑跳与物理跳不一致"当一等公民**处理的：128 位 nodeId 随机分配带来的"相邻 id 地理分散"这个前提、**routing table / neighborhood set / leaf set 三层**与 $b$ 的取舍（$b=4$ 时 $10^6$ 节点约 75 项 / 5 跳）、按前缀逐位逼近的三支路由与 0.02 / 0.006 的罕见情形、**route locality 的两条事实**（回不去 + 步长指数增长）与 WTF 第二阶段、**k 副本的 $k/2-1$ 前缀不匹配缺陷与密度启发式**（68/87 → 76/92，只比完美估计差约 2%）；含对 Plaxton / Chord / CAN 的亲口定位
- 04 · [[04-Kademlia|Kademlia]] —— 把**距离换成 XOR**，于是路由表结构、查找并行、以及"在线越久越可信"都从这一个选择推出来：XOR 的四条性质（含**单向性 → 后缀缓存**与**对称性 → 收发顺带更新 bucket**）、**k-bucket 的三条更新规则与"活节点永不移出"**、$\alpha$ 并发与 node lookup 六步、**路由表即按需生长的二叉树**与不平衡树的额外分裂、每小时重发布的两条优化与**指数反比过期**；含对 Chord（finger 表僵硬）与 Pastry（换度量造成不连续）的**亲口批评**，以及 $b>1$ 推广时"三篇前作都需次级表"这条技术论断
## 阅读顺序

**01 → 02 → 03 → 04。**

01 走的是**几何**这条路（坐标空间里的直线），02 到 04 走的是**标识符前缀/位**这条路（环上的逐段或逐位逼近）。先读 01 的好处是它的对照最刺眼：它**放弃了 $O(\log n)$ 的路径长度，换来每节点状态与 $n$ 无关** —— 这个取舍在后面三篇里会以不同形式反复出现。

后面的三篇内部是逐层收拢的关系：02 是这条线的基础形态（finger table），03 在它之上加了**前缀匹配与叶集**、并第一次正经处理"逻辑跳与物理跳不一致"；04 把度量换成 **XOR**，于是路由表的结构、查找的并行性、以及"节点长时间在线更可信"这件事都能从这一个选择里推出来。

## 与前几个专栏的关系

这一专栏的结论在今天主要**下沉成了中间件里的分片与路由层**，而不再体现为新的 P2P 覆盖网：

- [[04-一致性哈希算法|一致性哈希算法]] 是本专栏的前置 —— 它把"哈希环"这个工具交出来，02 到 04 都是在这个工具上做工程化；
- [[11-Ceph|Ceph]] 的 CRUSH 与 01 的坐标空间是两条**都能"算出位置"的路线**，但 CAN 要靠节点之间维持几何邻居关系，CRUSH 是纯函数、节点间不需要邻居表；
- [[03-Dynamo|Dynamo]] 与 [[05-Cassandra|Cassandra]] 则是把一致性哈希直接当作生产系统的分区手段（前者配虚拟节点，后者改成保序哈希 + 移 token）。
