# 分布式专栏导览

本专栏收录分布式系统的基础理论：一致性的取舍、副本的组织方式、以及没有全局时钟时事件顺序怎么定义。

本层是整棵子树的容器。四类专项各自成目录：**时钟**（时间怎么定义）、**一致性共识算法**（节点怎么达成一致）、**分布式事务**（跨节点操作怎么保证原子）、**区块链共识**（链场景下的共识选型）。另有四个目录承载"用这些理论造出来的具体系统"：**分布式存储**（已收 12 篇）、**P2P 与路由**（已收 4 篇）、**集群与运维**（已收 3 篇）、**分布式计算**（已收 6 篇，收完）。

## 阅读顺序

阅读顺序覆盖整棵子树，子专栏按内容依赖穿插在本层笔记之间：

**01 → 02 → 03 → 时钟 → 04 → 一致性共识算法 → 分布式事务 → 区块链共识**

01 是理论总纲；03 建立在 01 之上，正文里两处直接引用 CAP 的 C 与 A。03 与 01 之间不宜插读其他内容。

**时钟接在 03 后面**：03 讲的因果一致性，技术定义正是 [[03-逻辑时钟：Lamport 与向量|Lamport 时钟]] 与 [[03-逻辑时钟：Lamport 与向量|向量时钟]] 给的，两边互为前提。

**04 是分界线**：01 → 03 与时钟讲的都是「一致性的语义怎么定义」，04 起转到「数据与算法怎么组织」—— 数据怎么落到节点上，节点之间怎么达成一致，跨节点操作怎么保证原子（后两者见上面的子专栏）。

**四个实现类目录排在最后**：它们讲的是用这些理论造出来的具体系统，读完理论再看实现，对照关系最清楚。四者内部按「存储 → 计算 → P2P 与路由 → 集群与运维」走 —— 存储与计算是主线，另两条是支线。

**集群与运维这条支线是横切**：它不管数据怎么放、也不管节点怎么达成一致，只回答「**任务放哪、谁来发现彼此、出了问题怎么看见**」。三篇里 Chubby 提供最底层的协调原语，Borg 是搭在它上面的调度层，Dapper 是横切在两者之上的观测层；读完存储与共识再看它，能看清前两类系统在真实机队里是被什么托着的。
