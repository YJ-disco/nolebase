# 网络专栏导览

本专栏收录**数据在网络里怎么被搬运、怎么被保障**：单个协议的报文长什么样，地址怎么划、路由怎么匹配，一条连接从建立到关闭经历什么，丢包和拥塞了怎么办。

它与相邻专栏的边界是**层次而不是技术栈**：

| 不收 | 去哪看 | 本专栏只关心 |
| --- | --- | --- |
| 进程与线程怎么被调度、内存怎么被管理 | [[02-多线程与并发]]、[[01-cpu时间分片]] | 内核网络栈与用户态进程的交接点 |
| 数据怎么在磁盘与内存之间搬 | [[03-浅谈零拷贝技术 mmap与sendfile]] | 数据在内核里怎么走到网卡 |
| 多个节点怎么达成一致（Paxos、Raft、PBFT） | [[00-一致性共识算法专栏导览\|一致性共识算法]] | 承载这些协议报文的传输层本身 |

换个说法：上述专栏回答“用网络能造出什么系统”，本专栏回答“**一个字节从 A 到 B 要经过哪些约定**”。

## 阅读顺序

**01 → 02 → … → 14，编号就是阅读顺序**，整体从应用层往链路层走：01 立起骨架，02–04 是应用层，05–07 是传输层，08–09 是网络层，10–13 是网络接口层与主机接入，14 收尾落到内核实现。

**01** 是入口，只立起「应用层 / 传输层 / 网络层 / 网络接口层」这个骨架，后面各篇都在展开其中某一层。**02 → 03 → 04** 是应用层：01 举例用的那条「键入网址到页面显示」的路径就是 HTTP，所以 02 紧跟它；03 补上 HTTP 底下的 TLS，04 回答「已经有 HTTP 了，为什么还要 RPC 与 WebSocket」。**05 → 06 → 07** 是传输层：05 是母篇，把首部、状态机、确认与重传、流量与拥塞控制写到 wire level；06 讲它没讲的那另一半——会坏在哪里，规范与 Linux 实现分开说；07 是另一条路线，在 UDP 之上重建可靠传输。**08 → 09** 是网络层：08 讲首部、地址、路由与转发，09 补同层的 ICMP 与 ping，顺带把回环地址、`localhost` 与 `0.0.0.0` 分开。**10 → 13** 是网络接口层与接入：10 是帧与地址解析，11 是主机接入，12 从**设备**看这套机制（MAC 表与路由表），13 是 12 里 STP 那一段的完整展开。**14** 不引入新协议，只把前面几篇的分层落到 Linux 内核真实的调用链上，读完再回头看 05/08/10 的队列、重传与 NAPI 才有落点。

TCP 架在 IP 之上，IP 又架在以太网之上，顺着读下来每篇都在用前一篇的结论：TCP 的 MSS 协商受 IP 的路径 MTU 约束（[[05-TCP 协议]] §3.6 与 [[08-IP 协议与路由]] §5.3），而 IP 入网时的 1500 字节上限直接来自以太网的载荷上限（[[10-以太网与 ARP]] §1.3）。PMTU 黑洞的排查要同时用到 IP 的 `DF` 位与 TCP 的分段。

三篇内部各有一条线：

- TCP 按「先报文、再连接、再控制」走 —— 首部决定后面所有机制的表达方式，连接管理是状态机入口，可靠传输 / 流量控制 / 拥塞控制是三条并行回路；
- IP 按「先报文、再地址、再匹配、再转发」走 —— 首部字段是后面所有讨论的基础，地址决定前缀怎么算，最长前缀匹配是路由的核心，转发与分片把前几节串起来；
- 以太网按「先帧、再类型、再地址、再解析」走 —— 帧结构是载体，`EtherType` 决定载荷怎么解释，`MAC` 地址是转发依据，ARP 把 IP 地址接到这套地址上。
